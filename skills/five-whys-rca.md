# Five-Whys Root Cause Analysis
When the user reports a fault, defect, stoppage, or recurring problem on the line:
1. First `recall` the problem (station, code, symptom) to check whether the team has
   seen and fixed it before. If there is a known fix, lead with it.
2. State the problem clearly in one line (what, where, since when).
3. Ask or reason through "why?" up to five times to get past the symptom to the root
   cause. Stop earlier if the root cause is already established.
4. Give the countermeasure as short numbered steps, most-likely cause first, and
   include the part number when a replacement is involved.
5. If the cause is new or the fix worked, `remember` it as a one-line fix note so the
   next shift benefits. Offer to schedule a preventive-maintenance check when relevant.
